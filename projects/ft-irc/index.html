1. Background

Real-time IRC server

RFC 1459 호환 채팅 서버를 구현했습니다. 여러 클라이언트가 채널과 direct message를 통해 통신할 수 있도록 네트워크 연결, 사용자 상태, IRC 명령 처리를 하나의 서버로 구성했습니다.

4. Problem Solving

TCP stream boundaries

현상: TCP는 메시지가 아니라 연속된 바이트 스트림을 전달하므로, 한 번의 recv()가 완전한 IRC 명령 하나를 보장하지 않습니다.

해결: 클라이언트마다 수신 버퍼를 유지하고, 줄바꿈까지 수신된 완성 메시지만 CommandInvoker로 전달했습니다. 이 방식으로 분할되거나 합쳐진 수신 데이터에서도 명령 경계를 보존했습니다.

2. Architecture

UML diagrams

컴포넌트 수준의 메시지 처리 흐름과 주요 객체의 책임을 분리해 표현했습니다.

3. What I Did

Network and protocol handling

  • non-blocking 서버 소켓 생성, bind, listen, accept 흐름을 구현했습니다.
  • kqueue 이벤트 루프로 다수 클라이언트의 read/write 이벤트를 처리했습니다.
  • Client, Channel, User 상태와 PASS, NICK, JOIN, PRIVMSG 등 명령 디스패치를 구현했습니다.
  • 연결 종료와 오류 시 클라이언트 상태·fd를 정리하는 흐름을 구성했습니다.
5. Result

Multi-client channel server

  • 여러 클라이언트·채널·direct message를 처리하는 IRC 서버를 구현했습니다.
  • 이벤트 기반 I/O, 프로토콜 파싱, 상태 관리가 결합된 서버 구조를 완성했습니다.
