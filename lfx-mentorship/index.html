1. Background

Image metadata stopped before the runtime

urunc는 unikernel 실행에 필요한 메타데이터를 OCI 이미지 annotation에 저장합니다. 하지만 Docker, containerd, nerdctl, Kubernetes 같은 상위 도구를 거치면 해당 annotation이 runtime bundle의 config.json까지 자동으로 전달되지 않았습니다.

4. Problem Solving

Follow the image-to-runtime conversion path

원인 탐색: OCI 이미지 변환 규칙과 containerd의 CRI·non-CRI 경로를 분석해 manifest annotation이 runtime configuration으로 추출되지 않는다는 점을 확인했습니다. config label 대안도 검토했지만 구현마다 전파 보장이 달랐습니다.

선택: 이미지 자체의 자동 전파에 기대지 않고 shim이 containerd에 질의해 metadata를 가져오는 방향으로 문제를 재정의했습니다.

3. What I Did

Retrieve metadata from the runtime v2 shim

컨테이너 생성 단계에서 실행되는 urunc shim이 containerd API에 연결해 컨테이너와 이미지를 해석하고, content store에서 manifest를 읽어 필요한 metadata를 추출하도록 구현했습니다. 이후 annotation을 runtime config.json에 반영해 기존 urunc.json rootfs workaround 의존을 줄였습니다.

3개월 동안 메인테이너와 9회의 주간 온라인 sync를 진행하고, 설계 방향을 PoC로 구현해 annotation과 label 조회 오버헤드가 약 3ms임을 측정했습니다.

6. Remaining

Docker image-store support

현재 방향은 containerd와 nerdctl 경로에서 유효합니다. Docker는 자체 이미지 저장소를 사용할 수 있어, shim이 동일한 방식으로 metadata를 해석하지 못할 수 있습니다. Docker/Moby 경로는 추가 설계와 논의가 필요한 과제로 남았습니다.

멘토십 종료 후 community call에서 작업 내용을 발표했고, 조사 중 발견한 signal 처리 문제도 수정했습니다.
